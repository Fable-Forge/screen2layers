# screen2layers Output Format

## What Figma Gets

`layout.svg` uses `<image>` nodes to position bitmap layers. Figma imports these as separate image layers, which can be moved, hidden, resized, masked, and reordered. They are not true vector paths unless a later workflow manually redraws them.

This is useful for:

- Moving UI cards and buttons around.
- Keeping a background layer separate from foreground UI.
- Handing an artist or UI designer a structured starting point.
- Using Figma as a staging board for Cocos UI reconstruction.

## Output Files

- `background_working.png`: rough background generated by replacing extracted regions with sampled local color and blur.
- `slices/<index>_<name>.png`: transparent canvas PNG. Each slice has the same canvas size as the original screenshot, with only the selected region visible. This imports into Figma at the correct position even if dragged individually.
- `slices_cropped/<index>_<name>.png`: tightly cropped PNG for game atlases or manual layout.
- `layout.svg`: full-size SVG stack referencing `background_working.png` and cropped slices.
- `manifest.json`: machine-readable layer list.
- `preview.html`: browser preview.
- `debug/detected_boxes.png`: QA image showing bounding boxes.

## Good Manual Layer Names

Use short snake_case names:

- `background`
- `top_hud`
- `night_title`
- `letter_card_01`
- `letter_card_02`
- `primary_button`
- `status_strip`
- `back_button`
- `draft_panel`

## Common Limitations

- OCR is not bundled in v1. Rebuild text manually for editable Figma/Cocos layers.
- Intricate anime backgrounds need image inpainting for clean background removal.
- Auto detection prefers rectangular UI and may miss small icons or over-merge dense panels.
- Generated screenshots often contain imperfect text. Treat text in slices as visual reference, not source of truth.
